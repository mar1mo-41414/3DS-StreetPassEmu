# トラブルシューティング

実機とのすれちがいがうまくいかないときの切り分けガイド。このプロジェクトの開発中に
実際に踏んだ問題を、症状別にまとめている。

## まず確認する(クイック診断)

| 順 | 確認すること |
|---|---|
| 0 | USB Wi-Fiアダプタは**偽装MAC対応**(wifit3の`SPOOFABLE`)か([HARDWARE.md](HARDWARE.md)) |
| 1 | 3DS本体は**スリープ状態**(蓋を閉じた状態など、すれちがい待ち受け中)か。Wi-Fiが有効で、StreetPass Mii Plazaのすれちがいが有効になっているか |
| 2 | `STREETPASS_KEYSLOT_2E_FILE`が**実際にPythonプロセスまで届いているか**(`sudo`経由だと引き継がれない、下記A-2) |
| 3 | 送信するBoxは`mii_plaza_editor.py verify`で`outer HMAC`/`Mii CRC16`/`Mii CCM tag`が**3つ全て`OK`**か |
| 4 | `--cycle-seconds`は十分長いか(電波状況が悪いと接続確立に1〜2分かかる、下記B-3) |
| 5 | 実機との距離・向き・USBアダプタの位置を変えて、チャンネル(`--channel`)も試したか |

## A. 環境・ドライバ

### A-1. アダプタが認識されない / 会話が成立しない

| 症状 | 原因と対処 |
|---|---|
| `wlan_ifaces()`が空 | チップ非対応、または(Linuxで)USBデバイスノードの権限不足。`lsusb`でVID:PIDを確認し`tools/wifit3`の対応表と照合する。恒久的にsudoなしで使うには[SETUP.md](SETUP.md)の「Linuxでsudo無しで動かす」(udevルール)を適用する |
| `BringUpPermissionsError: ... Resource busy` | 別プロセスがUSBデバイスを掴んだまま(前回のテストが終了しきっていない等)。`ps aux \| grep streetpass`や`fuser -v /dev/bus/usb/.../...`で該当プロセスを確認して終了させる。`streetpass_loop.py`は自動リトライする |
| Probe Requestの往復は見えるのに、その先の会話が成立しない | アダプタ(チップ)が**偽装MAC宛のフレームにハードウェアACKを返せない**可能性が高い。「モニターモード対応」だけでは足りず、wifit3の`FAKE_MAC`が`SPOOFABLE`のチップが必要。[HARDWARE.md](HARDWARE.md)参照 |
| macOSで`libusb-package`のインストールに失敗する | Python 3.14ではwheelが無い。`uv run --python 3.12 ...`のようにPython 3.12を指定する |

### A-2. 実機のフレームは届いているのに会話が進まない(最頻出)

**環境変数`STREETPASS_KEYSLOT_2E_FILE`が未設定だと、エラーも出さずに黙って
応答しない**。実機からの暗号化フレームは正常に届き、こちらが復号も応答もしないため、
実機側が延々と再送してタイムアウトする。1時間以上気づけなかった実例がある。

`sudo`は既定で環境変数を引き継がないので、環境変数を明示的に渡す:

```bash
sudo -E env STREETPASS_KEYSLOT_2E_FILE=/path/to/streetpass_keyslot_2e.json \
    STREETPASS_FRIEND_CODE_FILE=/path/to/friend_code.json \
    /full/path/to/uv run --with pycryptodome python ../../scripts/streetpass_loop.py ...
```

### A-3. `sudo`配下で`uv`が見つからない

`env: 'uv': そのようなファイルやディレクトリはありません`。rootのPATHに`uv`が
含まれていない。`which uv`で得たフルパスを指定する。

## B. 接続・会話が成立しない

### B-1. ハンドシェイクが途中(Probe Request/Responseの往復)で止まる

電波状況(RF)の問題であることが多い。3DSとの距離・向き・USBアダプタの位置を変えて
再試行する。実機のStreetPassは特定のチャンネルに固定されない可能性があるため、
`--channel`を変えて試す価値がある(開発環境ではチャンネル1で安定して成立した)。
応答の送信タイミングに厳密な制約があるのかどうかは未検証
([STATUS.md](STATUS.md)の「未解決の課題」)。

### B-2. 相手(実機)が自分から何度もProbe Requestを送り直してくる

実機が「プローバー役」になり、こちらのAction frameへの応答を待っている状態。
こちらから同じ内容(ペイロード`0x0000`)のAction frameを返す必要がある。
`StreetPassResponder`は実装済みだが、独自のレスポンダーを書く場合は注意。

### B-3. `peer -> established`まで行くが応答Boxを受信できないままサイクルが終わる

接続確立が`--cycle-seconds`の終了間際になり、応答Boxの受信が間に合っていない。
送信自体は完了していることが多いが、確実にするには`--cycle-seconds 240`など長めにする。

### B-4. 複数のゲームを遊んでいる実機を検出できない

そうした実機はNintendo Tag内のサービス一覧の先頭に余分な1バイトを持ち、
`services_length = 1 + 5×N`になる(1サービスだけの実機では5の倍数ぴったり)。
この形式を想定していないパーサーは、その実機のブロードキャストを黙って無視する。
本リポジトリの`dot11.parse_nintendo_tag()`は対応済み。

## C. 送信したBoxが受理されない・表示がおかしい

### C-1. 緑ランプは点灯するのにMii広場に相手が現れない(黙って破棄される)

実機は検証に失敗したメッセージを**何のエラーも出さずに破棄する**。
`mii_plaza_editor.py verify <box>`で以下の3つが全て`OK`か確認する:

| 項目 | 失敗する典型的な原因 |
|---|---|
| `outer HMAC` | bodyを書き換えた後にHMACトレーラーを再計算していない(`mii_plaza_editor.py edit`は最後に自動で再計算する) |
| `Mii CRC16` | FFLStoreDataを手で書き換えてチェックサムを更新していない |
| `Mii CCM tag` | Miiブロックを**108バイト**として扱い、タグ末尾4バイトに元のBoxの古い値が残っている。Miiブロックは**112バイト(認証タグ16バイト全体)**。これを欠くと、Miiの中身を1ビット変えただけでも全て黙って破棄される。最も見つけにくい原因だった |

### C-2. 同じBoxを再送しても何も起きない

`messageId`が同じだと、実機側が既に受信済みとして重複排除する。再送するBoxは
`mii_plaza_editor.py edit --new-ids`でヘッダIDを作り直す。

### C-3. 意図したMiiの識別情報が毎回変わってしまう

`streetpass_loop.py`の`--fresh-each-cycle`は、ヘッダIDに加えて**送信者Miiの`mii_id`まで
毎回再生成する**。特定のMiiの識別情報(「n回目」の再会判定)を維持したい場合は付けない。

### C-4. 「初めまして」と出るのに詳細画面は「n回目」になる

ポップアップは「そのメッセージが初見か」、詳細画面のカウンタは「そのMiiと会った回数」
というように別のカウンタを見ている可能性が高い(未検証)。`--new-ids`で毎回
メッセージIDを変えていると、同じMiiでも「初めまして」と表示されることがある。

### C-5. 別人として登録されない / Mii QRコードとして読み込めない

- 識別情報(author_id/mii_id)が実機の既知のMiiと一致していると「n回目」になる。
  新規訪問者にしたいなら`--new-author-id --new-mii-id`で両方作り直す
- `mii_id`の先頭バイトは**上位4bitが`0x9`固定**でないと、MiiメーカーのQR読み込みで
  「これはMiiのQRコードではありません」と拒否される。`--new-mii-id`は自動で満たす

### C-6. コメントの書き換えで`ValueError: 16文字以下でなければ...`

自己紹介コメントは実機の入力欄の上限に合わせて16文字まで。全角・半角混在の文字列は
`len()`で数えた文字数で判定される。

### C-7. 居住地が「_ の ...です」になる

Boxの国名・地域名のテーブルが空です。`--prefecture`(例: `--prefecture 福岡県`)を付けてBoxを作り直すと、コードと名前が入ります
([CUSTOM.md](CUSTOM.md))。

### C-8. 通知や「最近遊んだ」のアプリのアイコンが黒い四角になる

アイコンが未指定だと、以前はデータが全部0でした。現在のビルドは灰色の代替アイコンを入れます。自分のアイコンは
`--large-icon` / `--small-icon` / `--header-icon`で指定してください。表示される名前はBoxのタイトル表(`--title`)ですが、
`--app-title-id`が本体設定(既定)のときだけは本体が自分で名前を付けます。

### C-9. Miiスタジオに持っていくと「編集できない」と出る

Miiの「編集を許可(コピー可)」フラグが立っていません。ランダムMiiは既定で編集許可です。他のMiiには`--allow-edit`
(GUIはMiiタブの「編集を許可する」)を使います。

### C-10. プロフィールの一文(犬か猫か・趣味・夢)が1〜2個しか出ない、コメントが出ない

実機では、会うたびに出るプロフィールの一文は一部だけで、訪問者のプロフィール画面にはまだ分からない項目が「-」と表示され、
同じ日の同じMiiはすれちがい回数が増えるだけです(1人1日1回の会話)。あいさつのコメントは、これまでの実機テストでは一度も
表示されていません([STATUS.md](STATUS.md)参照)。こちらの設定ミスではありません。

### C-11. Windows: `claim: Operation not supported or unimplemented on this platform`

アダプタは見えているが、まだWinUSBが当たっていません。`tools\wifit3`で`uv run --python 3.12 wifit3`を実行してWinUSBを
インストールするか、アダプタを抜き差ししてください([SETUP.md](SETUP.md) §3)。また、PowerShellでは bash の`export`ではなく
`$env:名前 = "..."`を使うこと。日本語を含むファイルはUTF-8で保存してください(現在のバージョンはWindowsのロケールに関係なくUTF-8で読みます)。

## D. NANDバックアップからの抽出

| 症状 | 原因と対処 |
|---|---|
| `decrypt_ctrnand.py`が失敗する | 生NANDバックアップ・`boot9`・`otp`は**同じ本体から**取ったものを使う。`ModuleNotFoundError: pyctr`は`pip install -e ".[dev]"`で解決 |
| 復号したイメージをマウントしても中身が空 / 想定と違う | `sudo mount -o loop,ro <img> <dir>`で読み取り専用マウントし、`data/<32桁のid0>/`配下を見る。id0は本体ごとに異なる |
| `extract_extdata_file.py`が「magicが違う」系のエラーで失敗する | このスクリプトが対応するのは**extdata**(`DIFF`コンテナ)のみ。システムセーブデータ(sysdata)は`DISA`という別のコンテナ形式で、pyctrで展開はできても中身が3DS独自の内部ファイルシステムで、本リポジトリには解析器が無い([STATUS.md](STATUS.md)) |
| `extract_console_miis.py list`に`翿`のような化けた名前が大量に出る | 未使用スロットは`0xff 0x7f`の繰り返しで埋まっており、UTF-16で`U+7FFF`(`翿`)に見える。本スクリプトは除外済みなので出ていれば最新版でない |
| フレンドコードを自動抽出できない | 未対応。本体の画面で確認して`friend_code.json`に手動で記入する([SETUP.md](SETUP.md) §4.4)。無くてもStreetPass自体は成立する |

## E. 解析・デバッグをする場合の落とし穴

- **ファイルオフセットとGhidra上のアドレス(VA)は`+0x00100000`ずれる**。生バイト列検索で
  見つけた位置をそのままGhidraに入れると、全く無関係なコードを読むことになる。
  「手法が通用しなかった」と結論する前にまずこれを疑う
- Ghidraの自動解析で`exit`系の関数が誤ってnoreturn扱いになり、後続のコードが
  関数として認識されないことがある。noreturnを外して関数を作り直すと読める
- 実機で実際に動いているのは、**SD等で配信されたアップデート版**の実行コード
  (Mii Plazaの場合)。NAND上のベース版を解析してアドレスを特定し、そのアドレスに
  ブレークポイントを張ると、無関係な命令を壊して実機がSDカードエラーになる。
  ブレークポイントを張る前に、必ず`x/i`等で実機上の命令が期待通りか確認する
- RosalinaのGDBスタブで「次に起動するアプリを強制デバッグ」を使うと、エントリポイントで
  停止する。ここから**`continue`せずに`detach`するとプロセスがクラッシュする**
  (本体への実害はない)。接続は基本1回勝負で、切断後はRosalinaから再度デバッグを
  開始し直す必要があり、ポート番号も変わる
- IPCコマンドヘッダ定数(`0x00030104`等)の32bit生バイト列検索は、有効な手がかりにも
  なるが誤検出も出る。ヒットした箇所は、正しいアドレス変換のうえで逆アセンブルして
  確認する([GAME_FORMATS.md](GAME_FORMATS.md)も参照)

詳細な解析環境の準備は[ANALYSIS_ENV.md](ANALYSIS_ENV.md)を参照。
